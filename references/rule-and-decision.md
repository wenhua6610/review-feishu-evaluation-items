# 规则效力与审查判定

## 材料效力顺序

默认按以下顺序确定权威性：

1. 最新有效的正式规则；
2. 最新有效的正式补充规则；
3. 当前项目或批次的正式任务说明；
4. 被正式文档明确授权的负责人解释；
5. 历史审核记录；
6. 历史合格样题；
7. 普通参考资料；
8. 评论、聊天记录和个人说明。

低等级材料不得覆盖高等级材料。历史样题只能帮助理解，不能自行产生新规则。

## “最新有效版本”判定

依次比较：

1. 明确的生效日期；
2. 正式版本号；
3. 发布日期；
4. 文档正文中的替代或废止声明；
5. 最后编辑时间。

不要仅因旧规则最近被编辑过就认定其最新。若以上线索冲突且会影响结论，将相关规则标为 `uncertainty`，请求规则负责人确认。

## 规则标准化

为每条可执行规则建立：

```json
{
  "rule_id": "R-001",
  "source_id": "SRC-001",
  "citation": "第3章/答案要求/第2条",
  "requirement": "参考答案应当唯一且可由题干确定",
  "force": "mandatory",
  "applies_to": ["question_stem", "reference_answer"],
  "pass_condition": "题干信息能够唯一推出参考答案",
  "fail_condition": "存在多个同等合理答案且规则无例外",
  "evidence_required": ["题干", "参考答案", "必要素材"],
  "exceptions": []
}
```

`force` 使用：

- `mandatory`：必须满足，可以产生违规；
- `conditional`：满足适用条件时强制；
- `advisory`：建议性要求，只能产生优化建议；
- `ambiguous`：强制性不明，只能产生待确认。

“建议、尽量、原则上、通常”等措辞默认不作为无条件强制要求；结合上下文仍不明确时使用 `ambiguous`。

## 适用性

先判断规则是否适用于当前题型、项目、对象和批次，再判断是否满足。不要把选择题规则应用到开放题，也不要把某一专业的要求扩展到所有题目。

若规则定义了例外：

1. 检查例外条件；
2. 记录命中的例外证据；
3. 不把符合例外的题目报为违规。

## 发现类型

### violation

同时满足以下条件才成立：

- 规则为 `mandatory`，或已满足 `conditional` 的适用条件；
- 题目证据明确违反失败条件；
- 相关材料足够完整；
- 不存在适用例外。

### uncertainty

用于：

- 关键材料缺失；
- 规则版本或效力冲突；
- 规则表述存在多种合理解释；
- 需要领域专家或工具验证但证据不足；
- 浏览或解析限制使证据不完整。

### advisory

用于规则未强制要求、但确实有助于质量的建议。必须明确标注“不影响本次基础合规结论”。

## 严重程度

- `blocker`：不修改无法发布，或无法完成基本审查；
- `major`：明确违反强制规则，影响有效性或可用性；
- `minor`：明确违反强制规则，但局部修正即可；
- `info`：待确认或非阻断建议。

严重程度不能替代发现类型；`advisory` 不得设为 `blocker`。

## 结论聚合

题目结论：

- 有 `violation` → `fail`；
- 无违规但有影响结论的 `uncertainty` → `pending`；
- 只有 `advisory` 或无发现 → `pass`。

总体结论：

- 任一题 `fail` → `fail`；
- 没有失败题，但任一题 `pending` → `pending`；
- 所有题通过且完整性为 `complete` 或缺失内容已证明无关的 `basic` → `pass`；
- 完整性为 `incomplete` 或 `unreviewable` → 不得 `pass`。

## 证据要求

每个违规必须包含：

- 规则 ID 和来源定位；
- 题目 ID、具体字段或文件位置；
- 足以复核的证据摘要；
- 为什么证据满足失败条件；
- 可执行的整改动作。

禁止：

- 用常识替代规则；
- 根据文风偏好判失败；
- 引用不存在的规则；
- 把材料缺失说成题目违规；
- 重复报告同一根因；
- 让优化建议改变总体通过结论；
- 擅自改写题目考查意图。
